# Module 8 — Plan-First Workflows

## Learning objectives
- Separate planning from execution so scope is agreed on before any code
  changes happen
- Understand how this differs from Document-Driven Development (Module
  6): a plan is typically ephemeral and generated by the agent for one
  task, where a spec is durable and authored by a human up front

## Key concepts
- Plan mode / approval gates: the agent proposes an approach and file-
  level scope; a human (or reviewer agent) approves before execution
  starts
- Architecture Decision Records (ADRs) as agent input for larger
  decisions — capturing *why*, not just *what*, so future plans don't
  re-litigate settled tradeoffs
- When plan-first beats DDD: the task is well-understood but the
  *approach* is what's risky (e.g., a multi-file refactor, a migration),
  so what needs review is the plan, not a requirements doc
- When plan-first is overkill: small, reversible changes where writing a
  plan costs more than just doing the thing and checking the diff

## Lab
Take a multi-file refactor (e.g., extracting a shared module, renaming a
widely-used interface). Require the agent to produce an explicit plan —
files it intends to touch and why — before any edit. Review and amend the
plan. Only then let it execute.

## Deliverable
The approved plan, the resulting diff, and a note on any place execution
diverged from the plan (and why).
