# Модуль 12 — Верификация и ревью результатов агента

## Цели обучения
- Выработать привычку верифицировать результат агента перед тем, как
  довериться ему, соразмерно риску изменения
- Распознавать специфичные для агентов режимы отказа, которые не
  проявляются в обычных чек-листах ревью кода, написанного человеком

## Ключевые концепции
- Галлюцинированные API: агент вызывает функцию/метод библиотеки,
  которого не существует, или существующего с иным поведением, чем
  предполагалось — обычно отлавливается реальным запуском кода, а не
  только чтением
- Незаметное расползание объёма задачи: агент «полезно» меняет что-то за
  пределами запрошенного объёма; ревьюйте диффы на размер и площадь
  затронутого, а не только на корректность
- Ревью безопасности для кода, сгенерированного ИИ: те же классы забот
  OWASP, что и для кода человека, плюс проверка того, что агент не
  срезал угол (например, SQL через конкатенацию строк), чтобы быстро
  удовлетворить тест
- Риск prompt injection: если агент читает недоверенный контент в ходе
  задачи (веб-страницу, тикет, файл вне репозитория), этот контент может
  содержать инструкции, адресованные агенту, а не вам — проверяйте это
  специально, когда задачи затрагивают внешние данные

## Лабораторная работа
Возьмите код, полученный в лабораторной работе одного из предыдущих
модулей. Проведите структурированный проход ревью: корректность по
критериям приёмки, проверка объёма относительно исходного запроса и
проход безопасности (обработка ввода, секреты, внедрённые инструкции,
если был задействован какой-либо внешний контент).

## Результат
Заполненный чек-лист ревью плюс находки — включая «ничего не найдено»,
если это честный результат.
