# Модуль 11 — Управление, безопасность и внедрение в команде

## Цели обучения
- Решать на уровне команды, а не отдельного человека, когда конкретная
  методология (из Модулей 3–7) обязательна, а когда опциональна для
  данного типа задачи
- Понимать, что измерять, чтобы знать, действительно ли разработка с
  агентами помогает

## Ключевые концепции
- Нормы раскрытия информации: должна ли команда знать, что PR был
  создан с помощью агента, и меняется ли из-за этого планка ревью?
- Требования к ревью по уровню риска: например, DDD + агент-ревьюер
  обязательны для всего, что касается аутентификации/биллинга/миграций
  данных; диалоговый режим подходит для внутренних инструментов и
  прототипов
- Фреймворк принятия решений: тип задачи → рекомендуемая методология
  (постройте его на основе сравнительной таблицы в
  [syllabus.md](../syllabus.md))
- Метрики: время цикла, доля откатов/revert, объём комментариев ревью
  на PR с участием агента vs. только человека — и ловушка измерения
  только скорости, пока качество регрессирует
- Типичные командные режимы отказа: методология выбирается по привычке,
  а не по соответствию задаче, спецификации написаны и никогда не
  обновляются, усталость от ревью из-за слишком большого объёма вывода
  агента слишком быстро

## Лабораторная работа
Используя сравнительную таблицу, постройте одностраничное дерево
решений: по описанию задачи — к какой методологии (или сочетанию) эта
команда обращается по умолчанию, и какая планка ревью требуется на
каждом уровне риска?

## Результат
Документ командной политики (дерево решений + требования к ревью + норма
раскрытия информации), написанный так, чтобы новый член команды мог
следовать ему без прохождения этого курса.
