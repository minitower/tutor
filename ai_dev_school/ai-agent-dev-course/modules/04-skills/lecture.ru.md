## Что такое skill и как он устроен (Слайды 4–8) — ~30 мин

### Слайд 4 — Проблема: процедуры раздувают контекст

Классическая ситуация: вы в десятый раз вставляете в чат один и тот же чек-лист. Или раздел CLAUDE.md вырос из факта в целую процедуру и грузится в каждую сессию, даже когда не нужен. Skill решает обе проблемы: это папка с SKILL.md и вспомогательными файлами, а тело загружается только когда skill используется. Вызвать можно вручную слэш-командой или позволить модели решить по описанию. Разграничение из цитаты запоминается легко: CLAUDE.md — факты, которые всегда верны; skill — процедура, нужная иногда.

### Слайд 5 — Анатомия skill

Анатомия. Обязателен только SKILL.md: frontmatter между тремя дефисами и инструкции ниже. Рядом — что угодно: подробный чек-лист, примеры, скрипты. На слайде минимальный рабочий пример — ревью диффа из модуля 12. Обратите внимание на три вещи: описание говорит и что делает, и когда использовать; в тексте есть ссылка на security.md, который прочитается только при необходимости; allowed-tools заранее разрешает две безопасные git-команды.

### Слайд 6 — Frontmatter: ключевые поля

Поля frontmatter. Все необязательны, но description рекомендуется — по нему модель решает, вызывать ли skill; вместе с when_to_use он ограничен примерно полутора тысячами символов. Дальше поля управления: disable-model-invocation, user-invocable, allowed-tools, disallowed-tools, context fork с agent, paths — активация только при работе с подходящими файлами, hooks. И поля открытого стандарта: license, compatibility, metadata. Важная деталь: неизвестное поле Claude Code игнорирует без ошибки — опечатка в имени поля молча отключит вашу настройку.

### Слайд 7 — Progressive disclosure: три уровня

Ключевая идея — progressive disclosure, три уровня. Первый: name и description всегда в контексте, это список навыков, чтобы модель знала, что есть. Второй: тело SKILL.md загружается, когда skill вызван. Третий: файлы по ссылке читаются, а скрипты не загружаются вовсе, а исполняются. Поэтому skill дешёвый: сто навыков стоят только списка описаний. Обратная сторона: при большом количестве часть описаний обрезается по бюджету, и модель теряет ключевые слова — держите описания короткими, с главным впереди.

### Слайд 8 — Кто и когда вызывает skill

Кто вызывает — важная таблица. По умолчанию и вы, и модель; описание всегда в контексте. С disable-model-invocation только вы: описание даже не грузится. С user-invocable false только модель — для фонового знания, которое не имеет смысла как команда. Практическое правило: всё с побочными эффектами — деплой, коммит, отправка — только disable-model-invocation true. Вы не хотите, чтобы модель решила деплоить, потому что код выглядит готовым. Ещё нюанс: вызванный skill остаётся в разговоре одним сообщением, а allowed-tools действует только на тот ход.

## Расположение, описание, аргументы, скрипты, fork (Слайды 9–13) — ~35 мин

### Слайд 9 — Где живут skills

Где живут skills. Personal — в домашнем каталоге, для всех ваших проектов. Project — в .claude/skills репозитория: коммитьте, и команда получит. Nested — в подкаталогах монорепозитория, подгружаются при работе с файлами там. Plugin — распространение команде через плагин. Enterprise — через managed settings организации. Плюс навыки аккаунта claude.ai. Старые файлы в .claude/commands продолжают работать: команды объединили со skills, а skills добавляют вспомогательные файлы и управление вызовом.

### Слайд 10 — Хорошее description

Описание — это то, что определяет, сработает ли skill. Слева плохое: «помогает с ревью» — слишком расплывчато, сработает не вовремя или никогда. Справа хорошее: что делает, когда использовать, какими фразами это просят. Формула: что делает плюс когда использовать плюс реальные фразы пользователя. Ключевой случай ставьте вперёд. Диагностика: срабатывает не вовремя — сужайте; не срабатывает — добавляйте реальные фразы, а пока вызывайте по имени.

### Слайд 11 — Аргументы и динамический контекст

Два приёма. Аргументы: при вызове слэш-командой с номером issue строка подставляется вместо ARGUMENTS, есть также позиционные и именованные. Динамический контекст: конструкция восклицательный знак и команда в обратных кавычках выполняется до отправки модели, а её вывод подставляется в текст — модель получает данные, а не команду. Это работает только в Claude Code: в чате claude.ai и через API такие блоки не выполняются.

### Слайд 12 — Скрипты: детерминизм внутри skill

Самый недооценённый приём — скрипты. Если что-то можно посчитать кодом — проверку скоупа, форматирование, парсинг — не просите модель, положите в scripts. Скрипт исполняется, а не читается: не тратит контекст и даёт одинаковый результат. Переменная CLAUDE_SKILL_DIR указывает на папку skill, а если тот же путь стоит и в тексте, и в allowed-tools, запуск проходит без запроса. Это детерминизм внутри недетерминированной системы — к идеям модуля 12.

### Слайд 13 — context: fork — skill в субагенте

Context fork запускает skill в отдельном субагенте с чистым контекстом. Пример — суммаризация PR: агент типа Explore только читает, дифф подставляется динамическим контекстом. Ограничение: субагент не видит вашей переписки, поэтому инструкции самодостаточны, а по умолчанию он работает в фоне. И предупреждение: fork годится только для skills с явным заданием — правила вроде «используй такие-то API-конвенции» без задачи вернут пустой результат.

## Выбор механизма и открытый стандарт (Слайды 14–15) — ~15 мин

### Слайд 14 — Skill, CLAUDE.md, hook, MCP, subagent

Как выбрать механизм. CLAUDE.md — факты, всегда верные, грузятся всегда; модель может проигнорировать. Skill — процедура по требованию; тоже может быть проигнорирована. Hook — обязательное поведение, вне модели, детерминированно. MCP — доступ к внешней системе. Subagent — изоляция контекста или роль. Главный вывод в цитате: skill — совет, hook — закон. Если правило должно выполняться всегда, скилл вас не спасёт — это модуль 13.

### Слайд 15 — Открытый стандарт и распространение

Открытый стандарт. Agent Skills — открытая спецификация формата SKILL.md, шесть полей. Claude Code понимает больше, но при загрузке в claude.ai или Skills API лишнее поле вызывает ошибку — для переносимости держитесь стандартных. Распространение: коммит в репозиторий, плагин, managed settings; примеры — репозиторий anthropics/skills. Есть расширение MCP Skills over MCP — доставка навыков через MCP. И связь с модулем 3: системы памяти вроде TencentDB Agent Memory идут дальше и извлекают навыки из завершённых задач — так опыт становится процедурной памятью.

## Безопасность и тестирование (Слайды 16–17) — ~20 мин

### Слайд 16 — Безопасность skills

Безопасность. Skill — это инструкции плюс скрипты, то есть выполнение кода с вашими правами. Тонкость: allowed-tools может выдать себе широкие права, и доверие к рабочей папке это поле не блокирует. Поэтому у skills из чужих репозиториев читайте allowed-tools до запуска. Сторонний skill — это цепочка поставок и prompt injection с авторитетом: его текст воспринимается как инструкция. Контроль: правила Skill в permissions — allow для конкретных, deny для опасных, deny на весь Skill отключает всё. Побочные эффекты — только вручную. И относитесь к skills как к коду: ревью, CODEOWNERS, пин версий плагинов.

### Слайд 17 — Тестирование и итерации

Тестирование. «Skill сработал» не значит «сделал правильно» — проверяйте дважды. Составьте пять запросов, где skill должен сработать, и пять, где нет; прогоняйте в свежей сессии. Сравните тот же запрос с skill и без: улучшилось ли и какой ценой. Инструменты: плагин skill-creator с evals и бенчмарком, claude plugin eval, claude plugin validate для битого YAML, doctor и debug. И ловушка: битый YAML не даёт ошибки — skill грузится без метаданных, слэш-команда работает, а модель его не находит.

## Лабораторная и итоги (Слайды 18–20) — ~10 мин

### Слайд 18 — Лабораторная — упакуйте процедуру в skill

Лаба. Выберите повторяющуюся процедуру из курса — ревью диффа, release notes, чек-лист расползания. Оформите skill: хорошее описание, детали в отдельном файле, детерминированная часть в скрипте. Составьте десять запросов и доведите срабатывание. Сравните с baseline без skill. Если у skill есть побочный эффект — disable-model-invocation, deny-правило и заметка по безопасности.

### Слайд 19 — Результат

Сдаём: папку skill, набор из десяти запросов с таблицей результатов — срабатывание и качество с skill против без — и заметку по безопасности. Таблица результатов важнее самого skill: она показывает, что студент проверил, а не поверил.

### Слайд 20 — Далее: Промптинг и постановка задач

Итог Модулей 2–4. MCP — руки: доступ к системам. Память — что агент помнит между сессиями. Skills — процедуры, которые загружаются, когда нужны. Все три — совет и возможности, а не гарантии: обязательное закрепляйте hook-ами и правами, а всё, что приходит извне, проверяйте как код. Дальше — Модуль 5, где учимся писать точные постановки задач; к MCP, памяти и навыкам вы вернётесь в капстоуне.
