## Проблема: процедуры раздувают контекст

- Вы снова и снова вставляете в чат один и тот же чек-лист или многошаговую процедуру
- Раздел `CLAUDE.md` вырос из факта в **процедуру** — и грузится в каждую сессию, нужна она или нет
- **Skill** — папка с `SKILL.md` (инструкции) и вспомогательными файлами; тело загружается **только когда skill используется**
- Вызвать можно `/имя` вручную или дать модели решить по описанию

> `CLAUDE.md` — факты, которые всегда верны. Skill — процедура, которая нужна иногда.

## Анатомия skill

```
.claude/skills/review-diff/
├── SKILL.md         # обязательный: frontmatter + инструкции
├── security.md      # подробный чек-лист (читается по ссылке)
├── examples.md      # примеры вывода
└── scripts/
    └── scope_check.sh   # исполняется, не загружается в контекст
```

```markdown
---
name: review-diff
description: Проводит структурированное ревью диффа по чек-листу (корректность, объём, безопасность, injection, переиспользование). Используй, когда просят проверить дифф, PR или «посмотри мои изменения» перед мержем.
allowed-tools: Bash(git diff *) Bash(git log *)
---
# Ревью диффа
1. `git diff --stat` — оцени объём относительно задачи.
2. Пять проходов: корректность → объём → безопасность → injection → переиспользование.
3. Выведи находки таблицей: файл, строка, риск, предложение.
Подробный чек-лист безопасности — в [security.md](security.md).
```

## Frontmatter: ключевые поля

| Поле | Зачем |
|---|---|
| `description` / `when_to_use` | **что делает и когда применять** — по нему модель решает, вызвать ли skill; лимит ~1 536 символов на пару |
| `name` | имя команды `/имя` (по умолчанию — имя папки) |
| `disable-model-invocation` | только вы можете вызвать (для деплоя, коммита, отправки) |
| `user-invocable: false` | только модель (фоновое знание) |
| `allowed-tools` / `disallowed-tools` | заранее разрешить / убрать инструменты на время хода |
| `context: fork` + `agent` | выполнить в изолированном субагенте |
| `paths`, `hooks`, `model`, `effort`, `arguments` | активация по путям, хуки, модель, усилие, именованные аргументы |
| `license`, `compatibility`, `metadata` | поля открытого стандарта Agent Skills |

Все поля необязательны, рекомендуется `description`. Неизвестное поле Claude Code молча игнорирует — опечатка не даст ошибки.

## Progressive disclosure: три уровня

Поэтому skill дешёвый: сотня навыков стоит только списка описаний. Если навыков много, часть описаний обрезается по бюджету — держите `description` коротким и с ключевым словом впереди.

<!-- Slide 8 -->

## Кто и когда вызывает skill

| Настройка | Вы (`/имя`) | Модель | Что в контексте |
|---|---|---|---|
| по умолчанию | да | да | описание всегда; тело — при вызове |
| `disable-model-invocation: true` | да | **нет** | описание не грузится; тело — при вашем вызове |
| `user-invocable: false` | нет | да | описание всегда; тело — при вызове |

- Побочные эффекты (`/deploy`, `/commit`, отправка сообщений) — только `disable-model-invocation: true`: не хотите, чтобы модель решила деплоить «потому что код готов»
- Вызванный skill остаётся в разговоре как одно сообщение; `allowed-tools` действует только на этот ход

## Где живут skills

| Уровень | Путь | Для кого |
|---|---|---|
| Enterprise | `.claude/skills/` в каталоге managed settings | все на машинах организации |
| Personal | `~/.claude/skills/<имя>/SKILL.md` | вы, во всех проектах |
| Project | `.claude/skills/<имя>/SKILL.md` | все в репозитории — коммитьте |
| Nested | `<подкаталог>/.claude/skills/` | монорепозитории: подгружается при работе с файлами там |
| Plugin | `<plugin>/skills/<имя>/` | команда через плагин, имя `/plugin:skill` |
| claude.ai | навыки аккаунта | Cowork, облачные сессии |

Старые `.claude/commands/*.md` продолжают работать — команды объединены со skills.

## Хорошее description

**Плохо**

«Помогает с ревью»

**Хорошо**

«Проводит структурированное ревью диффа по чек-листу (корректность, объём, безопасность). Используй, когда просят проверить дифф, PR или «посмотри мои изменения» перед мержем.»

- Формула: **что делает** + **когда использовать** + **фразы, которыми пользователь это попросит**
- Ключевой случай — в начале: длинное описание обрезается
- Срабатывает не вовремя → сузьте описание; не срабатывает → добавьте реальные фразы или вызывайте `/имя`

## Аргументы и динамический контекст

```markdown
---
name: fix-issue
description: Разобрать и исправить GitHub issue по нашему стандарту
argument-hint: [номер-issue]
disable-model-invocation: true
---
Исправь issue $ARGUMENTS: сначала воспроизведи, затем тест, затем правка.

## Состояние репозитория (выполняется ДО отправки модели)
!`git status --short`
```

- `/fix-issue 123` → `$ARGUMENTS` = `123`; есть `$0`, `$1` и именованные (`arguments:`)
- Строка с восклицательным знаком и командой в обратных кавычках выполняется **до** модели, вывод подставляется в промпт — модель получает данные, а не команду
- Работает только в Claude Code, не в чате claude.ai и не через API

## Скрипты: детерминизм внутри skill

```markdown
---
name: render-chart
description: Строит график из CSV. Используй, когда просят визуализировать данные из CSV.
allowed-tools: Bash(${CLAUDE_SKILL_DIR}/scripts/render.sh *)
---
Запусти `${CLAUDE_SKILL_DIR}/scripts/render.sh <файл.csv>` и покажи путь к PNG.
```

- Скрипт **исполняется**, а не читается моделью: не тратит контекст и даёт одинаковый результат каждый раз
- `${CLAUDE_SKILL_DIR}` — папка skill; одинаковый путь в тексте и в `allowed-tools` разрешает запуск без запроса
- Всё, что можно посчитать кодом (проверка скоупа, форматирование, парсинг), выносите в скрипт

## context: fork — skill в субагенте

```markdown
---
name: pr-summary
description: Суммаризирует изменения в pull request
context: fork
agent: Explore
allowed-tools: Bash(gh *)
---
## Контекст PR
- Дифф: !`gh pr diff`
## Задача
Кратко опиши изменения и риски.
```

- Skill выполняется в **отдельном субагенте** с чистым контекстом: он не видит вашей переписки — инструкции должны быть самодостаточными
- `agent:` выбирает тип (например, `Explore` — только чтение); по умолчанию работает в фоне
- Подходит для задач с явным заданием; правила вроде «используй такие-то конвенции API» в fork бессмысленны

## Skill, CLAUDE.md, hook, MCP, subagent

| Механизм | Для чего | Когда в контексте | Гарантия |
|---|---|---|---|
| `CLAUDE.md` | факты и конвенции, всегда верные | всегда | модель может проигнорировать |
| **Skill** | процедура по требованию | при использовании | модель может проигнорировать |
| **Hook** | обязательное поведение | вне модели | **детерминированно** |
| **MCP** | доступ к внешней системе | описания инструментов | права сервера |
| **Subagent** | изоляция контекста или роль | отдельный контекст | границы инструментов |

> Skill — совет. Hook — закон. Если правило должно выполняться всегда — это hook (модуль 13).

## Открытый стандарт и распространение

- **Agent Skills** (`agentskills.io`) — открытая спецификация формата `SKILL.md`; поля стандарта: `name`, `description`, `license`, `compatibility`, `metadata`, `allowed-tools`
- Claude Code понимает больше полей; но при загрузке в claude.ai или Skills API лишнее поле (`argument-hint`) даёт **ошибку** — для переносимости держитесь шести полей
- Распространение: коммит в `.claude/skills/`, **плагин**, managed settings организации; примеры — репозиторий `anthropics/skills`
- Расширение MCP **Skills over MCP**: навыки, обнаруживаемые через MCP (модуль 2)
- Системы памяти (модуль 3, актив Skill в TencentDB Agent Memory) идут дальше: **извлекают** навыки из завершённых задач

## Безопасность skills

- Skill — это **инструкции + скрипты**: выполнение кода и команд с вашими правами
- `allowed-tools` может сам выдать себе широкие права; «доверие к рабочей папке» это поле **не** блокирует — читайте `allowed-tools` у skills из чужих репозиториев
- Сторонний skill — цепочка поставок и **prompt injection с авторитетом**: его текст читается как инструкция
- Контроль: `Skill(deploy *)` в deny, `Skill(commit)` в allow; `Skill` в deny отключает все skills; побочные эффекты — `disable-model-invocation: true`
- Проверяйте skills как код: ревью, `CODEOWNERS` на `.claude/skills/`, пин версий плагина

## Тестирование и итерации

- «Skill сработал» ≠ «skill сделал правильно» — проверяйте **два** раза: срабатывает на нужных запросах и результат верный
- Набор: 5 запросов, где **должен** сработать, 5 — где **не должен**; прогон в свежей сессии
- Базовое сравнение: тот же запрос **с** skill и **без** него — стало ли лучше и какой ценой (токены, время)
- Инструменты: плагин `skill-creator` (evals, бенчмарк, тюнинг описания), `claude plugin eval` для skills в плагине, `claude plugin validate .claude/skills` для битого YAML, `/doctor` и `--debug`
- Битый YAML не даёт ошибки: skill грузится без метаданных, `/имя` работает, а модель его не находит

## Лабораторная — упакуйте процедуру в skill

1. Выберите повторяющуюся процедуру из курса (ревью диффа из модуля 12, черновик release notes, чек-лист расползания объёма)
2. Оформите skill: `SKILL.md` с хорошим `description`, подробности — в отдельном файле, детерминированную часть — в скрипт
3. Составьте набор из 5 «должен» + 5 «не должен» запросов и прогоните в свежих сессиях; доведите срабатывание
4. Сравните результат с skill и без него; запишите разницу по качеству и стоимости
5. Для skill с побочным эффектом задайте `disable-model-invocation: true` и добавьте deny-правило; заметка по безопасности

## Далее: Промптинг и постановка задач

Skill — процедурная память: она загружается, когда нужна, и не раздувает контекст. Но это совет, а не закон: обязательное закрепляйте hook-ами, а чужие skills проверяйте как код.

Теперь у агента есть руки (MCP), память и навыки — дальше учимся давать ему точные инструкции.
