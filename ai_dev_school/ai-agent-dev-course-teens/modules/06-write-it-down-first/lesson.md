# Module 6 — Write It Down First

## Big idea

For anything bigger than a quick fix, writing down what you want
*before* the agent starts building — like a short game design doc or a
one-page project brief — saves more time than it costs. You catch your
own unclear thinking on paper, before it turns into the wrong code.

A good one-page plan covers:
- **Goal** — what this is supposed to do, in plain language
- **Not this** — what's explicitly out of scope (stops the agent from
  "helpfully" adding extra stuff you didn't ask for)
- **How it should behave** — the important cases, including the tricky
  ones you already know about
- **Done means** — how you'll know it actually works

## Why it matters

This is the same idea professional teams call "document-driven
development" — the doc is the source of truth, not a chat conversation
that gets forgotten five minutes later.

## Hands-on task

1. Pick a real feature for your project — something with at least one
   tricky edge case you can already think of.
2. Write the one-page plan using the four sections above. Keep it to
   about a page — this isn't a school essay.
3. Give the agent *only* the plan as the task — no extra verbal
   explanation.
4. Check the result against your "done means" section.

## Checkpoint

- What did the agent get right straight from the plan?
- What did you have to go back and add to the plan, because it turned
  out you'd left something out or the agent guessed wrong?

## Supervisor note

Standard supervision. This module's checkpoint is a good one to actually
read together — the "what did you leave out" list is often the most
useful part of the whole exercise.
