# Module 0 — Meet Your AI Coding Partner

## Big idea

An AI coding agent like Claude Code isn't the autocomplete you've maybe
seen suggesting the next word in a text message, and it isn't magic
either. It's a partner that can actually **read your files, write new
code, run commands, and check whether what it did worked** — in a loop,
on its own, until it thinks the task is done. That's what makes it
different from a search engine or a chatbot: it can take real actions,
not just talk about them.

That also means it needs boundaries, same as any partner you're handing
real work to. It only does what you tell it (or what it reasonably
infers you meant) — this whole course is about getting good at the
"telling it" part.

## Why it matters

Everything later in this course assumes you have a working, honest
mental model of what's actually happening when you type a request and
code appears. If that model is "it's magic, I just ask and it works,"
you won't notice when it gets something wrong — and it will, sometimes
confidently.

## Hands-on task

1. Confirm your sandboxed project folder is set up (see
   [SUPERVISOR-GUIDE.md](../SUPERVISOR-GUIDE.md) — do this with your
   supervisor if you haven't already).
2. Open Claude Code in that folder.
3. Ask it to do one tiny, safe, reversible thing — e.g. "create a file
   called `hello.txt` with a short message in it."
4. Before approving anything, read what it says it's about to do. After
   it finishes, look at the actual file it created.
5. Now ask it a question about itself: "what tools do you have access to
   in this session, and what would you need my permission for?"

## Checkpoint

In your own words (a few sentences, spoken or written):
- What did the agent actually *do*, step by step, to complete the task?
- What's one thing it would need your permission for, and why do you
  think that boundary exists?

If your answer is "it just did it," that's a sign to slow down and
re-watch the session — the goal here isn't the file, it's noticing the
steps.
