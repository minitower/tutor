# Модуль 2 — Подключай: MCP

## Главная идея

До сих пор твой агент жил в «пузыре»: он видит папку проекта — и всё. Он не знает, что лежит в таблице очков твоей игры, в данных твоего бота или в документации библиотеки. **MCP** (Model Context Protocol) — это общий стандарт «разъёма» для ИИ, что-то вроде USB-C: один раз пишешь маленькую программу-сервер, и любой агент может подключиться и пользоваться её *инструментами*. Но у подключения есть цена: сервер — это программа, которая запускается на твоём компьютере, и всё, что она возвращает агенту, — ненадёжный текст (это анонс Модуля 12).

## Почему это важно

Настоящие проекты упираются в данные и сервисы за пределами папки: таблица очков, база бота, календарь клуба. Если знать MCP, ты подключаешь их аккуратно и понимаешь, что при этом разрешаешь — а не просто копируешь чужую команду из интернета.

## Практическое задание

**Часть A — сделай свой мини-сервер:**
1. Для своего проекта выбери маленький источник данных: файл `scores.json`, список уровней, команды бота.
2. Напиши сервер с **одним** инструментом «только чтение» (как на слайде 8) — можно попросить агента набросать, но читай каждую строчку.
3. Проверь его без агента: `npx @modelcontextprotocol/inspector python scores_server.py`.

**Часть Б — подключи и спроси:**
1. Подключи сервер: `claude mcp add --transport stdio scores -- python scores_server.py`.
2. Задай агенту три вопроса, на которые можно ответить только через этот инструмент. Запиши, какие вызовы он сделал.

**Часть В — попробуй сломать:**
1. Попроси агента *изменить* данные через сервер. Что произойдёт? Почему? (У сервера нет такого инструмента.)
2. Составь мини-чек-лист «можно ли подключить этот сервер» из 5 пунктов.

## Чекпоинт

- Твой код сервера и трасса вызовов из Части Б
- Твой чек-лист из 5 пунктов
- Одно предложение: почему результат инструмента нельзя считать «инструкцией от меня»

## Заметка для куратора

**Модуль повышенного внимания.** Сервер MCP — программа, которая выполняется на компьютере подростка. Подключайте только серверы, которые он написал сам или которые вы вместе проверили (официальные примеры). Никаких токенов и паролей от личных аккаунтов, никаких серверов с записью в важные данные. Держите права на чтение и работайте только с тестовыми данными.
