## Проблема: «у меня работает»

- У разработчика Python 3.12, на сервере — 3.9
- Библиотеке нужна системная зависимость (`libpq`), которой нет на сервере
- Два проекта на одном сервере требуют разных версий одного пакета
- Новый сотрудник настраивает окружение два дня

**Контейнер** упаковывает приложение **вместе с окружением**: интерпретатор, библиотеки, системные пакеты, конфиги.

<!-- Slide 5 -->
## Виртуальная машина vs контейнер

| | Виртуальная машина | Контейнер |
|---|---|---|
| Что изолирует | Целый компьютер со своей ОС | Процесс(ы) на общем ядре |
| Размер | Гигабайты | Десятки–сотни мегабайт |
| Запуск | Минуты | Секунды и меньше |
| Изоляция | Сильная (гипервизор) | Хорошая, но ядро общее |
| Плотность | Десятки на сервер | Сотни на сервер |

Контейнер — это **не маленькая ВМ**, а обычный процесс Linux, которому ограничили обзор и ресурсы.

<!-- Slide 6 -->
## Под капотом: три механизма Linux

- **Namespaces** — что процесс **видит**: свои PID, сеть, файловую систему, hostname, пользователей
- **cgroups** — сколько процесс **может взять**: CPU, память, диск, число процессов
- **Слоистая файловая система (OverlayFS)** — образ из слоёв только для чтения + тонкий слой для записи сверху

На Windows и macOS Docker Desktop запускает лёгкую Linux-ВМ, и контейнеры живут в ней.

---

<!-- Slide 7 -->
## Образ, контейнер, реестр

- **Образ (image)** — шаблон только для чтения: файлы + метаданные (что запускать, какие порты)
- **Контейнер** — запущенный экземпляр образа со своим слоем для записи
- **Реестр (registry)** — хранилище образов: Docker Hub, GitHub Container Registry, реестр облака
- **Тег** — человеческое имя версии (`slot-api:1.4.0`, `latest`); **digest** (`sha256:…`) — точный неизменяемый отпечаток

Аналогия: образ — класс, контейнер — объект.

<!-- Slide 8 -->
## Архитектура Docker

```
docker CLI  →  Docker Engine (dockerd)  →  containerd  →  runc  →  процесс
   ваша           демон: API, сборка,       управляет        создаёт namespaces
   команда        сети, тома                контейнерами     и cgroups
```

- **OCI** — открытый стандарт образов и рантайма: образ, собранный Docker, запустит Podman или Kubernetes
- **Podman** — альтернатива без демона, совместимая по командам
- Kubernetes использует containerd напрямую, без Docker Engine

## Dockerfile

```dockerfile
FROM python:3.12-slim

WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY app/ ./app/

EXPOSE 8000
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

Каждая инструкция (`FROM`, `RUN`, `COPY`) создаёт слой.

---

<!-- Slide 10 -->
## Кэш слоёв и порядок инструкций

```dockerfile
# Плохо: любая правка кода → переустановка всех зависимостей
COPY . .
RUN pip install -r requirements.txt

# Хорошо: зависимости меняются редко — их слой берётся из кэша
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
```

Правило: **редко меняющееся — выше, часто меняющееся — ниже**. Плюс `.dockerignore`: `.git`, `node_modules`, `.venv`, `.env`.

<!-- Slide 11 -->
## Multi-stage сборка

```dockerfile
# Этап 1: сборка — со всеми инструментами
FROM node:22 AS build
WORKDIR /src
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Этап 2: запуск — только результат
FROM nginx:alpine
COPY --from=build /src/dist /usr/share/nginx/html
```

Итоговый образ фронтенда: ~1,2 ГБ → ~50 МБ. Компиляторов и исходников в продакшене нет.

<!-- Slide 12 -->
## Маленькие и безопасные образы

| Базовый образ | Размер | Когда |
|---|---|---|
| `python:3.12` | ~1 ГБ | Почти никогда для продакшена |
| `python:3.12-slim` | ~130 МБ | По умолчанию |
| `alpine` | ~5 МБ основа | Осторожно: musl вместо glibc, бывают сюрпризы с колёсами Python |
| `distroless` | Минимум | Нет даже shell — меньше поверхность атаки |

Плюс: запуск **не от root** (`USER app`), **никаких секретов в слоях**, фиксированные версии.

<!-- Slide 13 -->
## Запуск: порты, тома, переменные

```bash
docker run -d --name slot-api \
  -p 8000:8000 \
  -e DATABASE_URL=postgresql://... \
  -v slot-uploads:/app/uploads \
  --restart unless-stopped \
  --memory 512m --cpus 1 \
  slot-api:1.4.0
```

- `-p` порт хоста : порт контейнера · `-e` конфигурация через окружение · `-v` именованный том · `--memory/--cpus` лимиты (cgroups)
- Контейнер **одноразовый**: всё, что записано внутрь без тома, пропадёт при пересоздании
- **Тома (volumes)** — данные, которые переживают контейнер; **bind mount** — папка хоста (для разработки)

## Сети и healthcheck

- Контейнеры в одной пользовательской сети видят друг друга **по имени сервиса**: `postgres:5432`
- Наружу публикуем только то, что нужно (`-p`); БД наружу не открываем
- **Healthcheck** — команда, которая проверяет, что приложение действительно живо, а не просто запущено

```dockerfile
HEALTHCHECK --interval=10s CMD curl -f http://localhost:8000/health || exit 1
```

## Docker Compose: всё приложение в одном файле

```yaml
services:
  api:
    build: ./api
    environment:
      DATABASE_URL: postgresql://slot:${DB_PASSWORD}@postgres:5432/slot
      REDIS_URL: redis://redis:6379
    depends_on:
      postgres: { condition: service_healthy }
    ports: ["8000:8000"]
  worker:
    build: ./api
    command: arq app.worker.Settings
  postgres:
    image: postgres:17
    volumes: [pgdata:/var/lib/postgresql/data]
    healthcheck: { test: ["CMD", "pg_isready", "-U", "slot"] }
  redis:
    image: redis:7
volumes:
  pgdata:
```

## Compose: разработка и продакшен

- `docker compose up` — поднять всё; `down` — остановить; `logs -f api` — смотреть логи
- **Разработка:** bind mount кода + автоперезагрузка; `compose.override.yaml` подхватывается автоматически
- **Продакшен:** только готовые образы из реестра, секреты из окружения, `restart: unless-stopped`
- Compose на одном VPS — честный вариант для продакшена небольшого проекта (Модуль 11)

<!-- Slide 17 -->
## Безопасность образов

- **Сканирование уязвимостей:** Trivy, Docker Scout, Grype — в CI на каждую сборку
- **Фиксация версий:** `postgres:17.2`, а не `latest`; для максимальной точности — digest
- **Не root** внутри контейнера
- **Секреты** — через переменные окружения или secrets, не в `Dockerfile` и не в слоях
- **Минимальный образ** — меньше пакетов, меньше уязвимостей

<!-- Slide 18 -->
## Docker и ИИ-агенты

- Контейнер — **песочница** для агента: агент запускает код и тесты, не трогая вашу систему
- Агенты хорошо пишут Dockerfile, но часто: копируют всё до установки зависимостей, забывают `.dockerignore`, оставляют root
- Проверка простая: пересобрать после правки одной строки кода и посмотреть, сколько слоёв взялось из кэша
