# Модуль 8 — Docker: упаковываем приложение

## Цели обучения
- Понимать, что такое контейнер изнутри и чем он отличается от виртуальной машины
- Писать хороший Dockerfile и Compose-файл для приложения из нескольких сервисов
- Понимать, почему контейнер стал стандартной единицей поставки

## План лекции
1. Проблема: «у меня работает», конфликты зависимостей, расхождение окружений
2. VM vs контейнер: гипервизор + полноценная ОС vs общее ядро + изолированный процесс
3. Под капотом: Linux namespaces (изоляция), cgroups (лимиты), слоистая файловая система (OverlayFS)
4. Основные понятия: образ, слой, контейнер, реестр (Docker Hub, GHCR), тег vs digest
5. Архитектура Docker: CLI → Docker Engine (демон) → containerd → runc; стандарт OCI; Podman как альтернатива
6. Dockerfile: `FROM`, `RUN`, `COPY`, `CMD`/`ENTRYPOINT`; кэш слоёв и порядок инструкций; `.dockerignore`
7. Multi-stage сборка; маленькие и безопасные образы: slim, alpine, distroless, пользователь не root, никаких секретов в слоях
8. Запуск: порты, volumes vs bind mounts, сети, переменные окружения, healthcheck, политики перезапуска
9. Docker Compose: всё приложение в одном файле; зависимости сервисов, локальная разработка vs продакшен
10. Основы безопасности: сканирование образов (Trivy, Docker Scout), фиксация версий

## Лабораторная работа
Напишите Dockerfile для фронтенда и бэкенда «Slot» и `compose.yaml` с PostgreSQL, Redis и воркером. Уменьшите образ бэкенда с помощью multi-stage сборки.
- **С агентом:** попросите агента проверить Dockerfile на порядок кэша, размер образа и безопасность; проверьте каждое предложение пересборкой.

## Результат
`docker compose up` поднимает весь «Slot» локально + размер образа до/после.
