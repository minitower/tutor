# Модуль 4 — Проектирование API: контракт, на который можно положиться

## Цели обучения
- Проектировать ресурсы, методы, коды ответов и ошибки так, чтобы клиент мог их предсказать, не читая код
- Сделать API устойчивым к повторам, двойным кликам и одновременным правкам
- Развивать API, не ломая существующих клиентов

## План лекции
1. API — это продукт и контракт: от него зависят фронтенд, мобильные приложения, партнёры и ИИ-агенты; опубликованный API трудно изменить
2. Ресурсы и URL: существительные, коллекции во множественном числе, разумная вложенность; глаголы в URL как антипаттерн
3. Методы HTTP: безопасные и идемпотентные методы и почему это важно для повторов
4. Коды ответов, которые действительно нужны: 200, 201, 204, 400, 401, 403, 404, 409, 422, 429, 5xx
5. Единый формат ошибок для всего API: Problem Details (RFC 9457)
6. Валидация на границе; ошибки по полям
7. Пагинация (offset vs cursor), фильтрация, сортировка; соглашения об именах и данных (ISO 8601 с часовым поясом, деньги в минимальных единицах)
8. Идемпотентность: заголовок `Idempotency-Key` и как его реализовать
9. Одновременные правки: ETag, `If-Match`, оптимистичная блокировка
10. Версионирование и развитие: добавляющие и ломающие изменения, вывод из эксплуатации и заголовок `Sunset`
11. Авторизация, права (scopes) и лимиты запросов (`429` + `Retry-After`)
12. Вебхуки: подпись (HMAC), повторы, идемпотентные получатели
13. REST vs GraphQL vs gRPC vs WebSocket/SSE: что когда подходит
14. Contract-first: OpenAPI → мок-сервер, сгенерированные клиенты, линтинг (Spectral), контрактные тесты (Schemathesis)
15. API для ИИ-агентов: описания, примеры, предсказуемые ошибки; почему с агентами идемпотентность обязательна

## Лабораторная работа
Доработайте OpenAPI «Slot» из Модуля 1 и реализуйте изменения: формат ошибок Problem Details, cursor-пагинация для слотов, `Idempotency-Key` на `POST /bookings`, ETag при изменении записи, подписанный вебхук `booking.created`. Проверьте спецификацию Spectral и прогоните Schemathesis по работающему API.
- **С агентом:** попросите агента проверить OpenAPI на несогласованность (имена, коды ответов, пропущенные ошибки), затем написать запуск Schemathesis; каждую находку сверьте со спецификацией сами.
