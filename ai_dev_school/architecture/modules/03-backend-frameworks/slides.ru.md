## Что делает любой бэкенд

1. **Роутинг** — какой код обрабатывает `POST /api/bookings`
2. **Валидация** — пришёл ли телефон, существует ли слот
3. **Аутентификация и авторизация** — кто это и что ему можно
4. **Бизнес-логика** — нельзя записаться на прошедший слот
5. **Доступ к данным** — БД, кэш
6. **Фоновые задачи** — уведомления, отчёты
7. **Интеграции** — Telegram, платежи, LLM

Фреймворк даёт готовые 1–3 и 5; ваша работа — 4.

## Python: FastAPI

```python
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel

app = FastAPI()

class BookingCreate(BaseModel):
    slot_id: int
    client_name: str
    phone: str

@app.post("/api/bookings", status_code=201)
async def create_booking(data: BookingCreate):
    booking = await book_slot(data)   # бизнес-логика
    if booking is None:
        raise HTTPException(409, "slot_taken")
    return booking
```

Типы → валидация + документация OpenAPI автоматически. Async. Лучший выбор для API и ИИ/ML-сервисов.

- «Батарейки в комплекте»: ORM, миграции, админка, авторизация, формы, шаблоны

## Rust

```rust
async fn create_booking(Json(data): Json<BookingCreate>) -> impl IntoResponse {
    match book_slot(data).await {
        Some(b) => (StatusCode::CREATED, Json(b)).into_response(),
        None => (StatusCode::CONFLICT, "slot_taken").into_response(),
    }
}
```

- **Axum**, **Actix Web** — максимум производительности, безопасность памяти без сборщика мусора
- Компилятор ловит целые классы ошибок (гонки данных, null)
- Цена: высокий порог входа, медленная компиляция
- Лучший выбор: горячие участки, прокси, CPU-нагрузка, системы, где важна каждая миллисекунда

## Модели конкурентности

Как обслужить 10 000 клиентов, которые ждут ответа от БД?

| Язык | Модель | Суть |
|---|---|---|
| Python | GIL + `asyncio` | Один поток Python за раз; async переключается на время ожидания I/O |
| Node.js | Event loop | Один поток, всё I/O неблокирующее |
| Go | Горутины | Тысячи лёгких потоков, рантайм раскладывает по ядрам |
| Rust | Tokio (async) | Как asyncio, но без GIL, на всех ядрах |
| Java | Виртуальные потоки | Пишем блокирующий код, JVM делает его дешёвым |

<!-- Slide 12 -->
## Что на самом деле даёт async

- Async ускоряет **ожидание**, а не **вычисления**
- Пока запрос ждёт БД 50 мс, процесс обслуживает другие запросы
- Тяжёлый расчёт в async-функции **блокирует всех**
- Python: CPU-задачи → отдельные процессы, очередь или расширение на Rust/C
- Подробно о производительности — в Модуле 6

## Данные: SQL vs NoSQL

| | SQL (PostgreSQL, MySQL) | NoSQL (MongoDB, Redis, DynamoDB) |
|---|---|---|
| Модель | Таблицы и связи | Документы, ключ-значение |
| Гарантии | Транзакции, ограничения | Зависит от системы |
| Схема | Строгая, миграции | Гибкая |
| Когда | По умолчанию для бизнес-данных | Кэш, сессии, логи, особые нагрузки |

Для «Slot»: PostgreSQL — связи и защита от двойной записи (ADR-0002).

## ORM, query builder, SQL

| Подход | Примеры | Плюсы | Минусы |
|---|---|---|---|
| ORM | SQLAlchemy, Django ORM, Prisma, GORM | Объекты вместо SQL, меньше кода | Скрытые медленные запросы (N+1) |
| Query builder | SQLAlchemy Core, Kysely, sqlc | Контроль + типы | Больше кода |
| Чистый SQL | asyncpg, pgx, sqlx | Максимум контроля и скорости | Всё вручную |

**Миграции** (Alembic, Django migrations, goose) — версии схемы БД в git, как код.

## Авторизация

| Подход | Как работает | Когда |
|---|---|---|
| **Сессии** | ID сессии в cookie, данные на сервере | Классические веб-приложения |
| **JWT** | Подписанный токен с данными у клиента | API, мобильные клиенты, микросервисы |
| **OAuth / OIDC** | «Войти через Google / Яндекс / Telegram» | Не хотите хранить пароли |

Правила: пароли — только хэш (argon2, bcrypt); токены — с коротким сроком жизни; права проверяет **сервер**.

## Решают не бенчмарки

- Для 95% проектов узкое место — **БД и сеть**, а не язык
- Скорость разработки команды важнее скорости языка
- Экосистема: есть ли библиотеки под ваши интеграции?
- Найм: кого вы найдёте через год?
- Знакомство агентов: популярные стеки агенты пишут лучше

> Выбирайте скучную технологию, если у вас нет причины выбрать другую.

## Структура API «Slot» на FastAPI

```
app/
  main.py            # создание приложения, роутеры
  api/bookings.py    # эндпоинты: только HTTP
  services/booking.py# бизнес-логика: правила записи
  db/models.py       # таблицы
  db/repo.py         # запросы к БД
  schemas.py         # Pydantic: вход и выход API
migrations/          # Alembic
tests/               # pytest, ссылки на TC-xx
```

Слои: HTTP → логика → данные. Логику можно тестировать без HTTP и БД.
