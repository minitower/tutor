# Модуль 3 — Бэкенд: языки и фреймворки

## Цели обучения
- Понимать, что делает бэкенд и что даёт любой фреймворк
- Знать основные бэкенд-стеки, их сильные и слабые стороны
- Выбирать язык и фреймворк под конкретный проект и обосновывать выбор

## План лекции
1. Что делает бэкенд: роутинг, валидация, авторизация, бизнес-логика, работа с БД, фоновые задачи, интеграции
2. Python
   - FastAPI: async, type hints, автоматический OpenAPI; лучший выбор для API и AI/ML-сервисов
   - Django (+ DRF): «всё включено», админка, ORM; для контентных и CRUD-продуктов
   - Flask, Litestar: минималистичные альтернативы
3. Go
   - `net/http` (с роутингом из Go 1.22 его хватает для большинства сервисов), Gin, Echo, chi
   - Один бинарник, горутины, мало памяти; для высоконагруженных API, инфраструктурных утилит, микросервисов
4. Node.js / TypeScript: Express, Fastify, NestJS, Hono; один язык на фронте и бэке, realtime
5. Rust: Axum, Actix Web; максимум производительности и безопасности, высокий порог входа; горячие участки, прокси, CPU-нагрузка
6. Java/Kotlin (Spring Boot, Ktor) и C# (ASP.NET Core): энтерпрайз, банки, большие команды
7. Модели конкурентности: GIL + asyncio, горутины, event loop, Tokio, виртуальные потоки; что на самом деле даёт «async»
8. Слой данных: SQL vs NoSQL, ORM vs query builder vs чистый SQL, миграции
9. Авторизация: сессии vs JWT, OAuth/OIDC, никогда не хранить пароли открытым текстом
10. Какой стек для какого проекта: MVP, CRUD/админка, высоконагруженное API, AI/ML-сервис, realtime, CLI/инфраструктура

## Лабораторная работа
Реализуйте API «Slot» по OpenAPI из модуля 1 на FastAPI с PostgreSQL, миграциями и тестами. Реализуйте один эндпоинт повторно на Go (или Rust) и сравните.
- **С агентом:** дайте агенту файл OpenAPI + тест-кейсы и попросите реализовать эндпоинты через тесты; проверьте, что он не выдумал полей, которых нет в контракте.

## Результат
Рабочее API с миграциями и тестами + заметки сравнения (объём кода, скорость написания, инструменты, цифры в рантайме).
