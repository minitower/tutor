# Модуль 13 — Итоговый проект: запускаем

## Цели обучения
- Собрать все слои курса в один живой продукт
- Защитить архитектурные решения с помощью ADR и цифр
- Провести реальный запуск и разобрать его результаты

## Требования
1. **Документация:** vision, user stories с критериями приёмки, BPMN основного процесса, C4-диаграмма контейнеров, OpenAPI, ADR (модуль 1)
2. **Фронтенд:** публичная SEO-страница + интерактивная часть; выбор фреймворка обоснован (модуль 2)
3. **Бэкенд:** API с авторизацией, тестами и одной фоновой задачей (модуль 3)
4. **Проектирование API:** единый формат ошибок, пагинация, идемпотентная запись, версионирование; OpenAPI соответствует коду (модуль 4)
5. **Данные:** ограничения, при которых двойная запись невозможна, миграции, хотя бы одна миграция без простоя (модуль 5)
6. **Производительность:** нагрузочный тест с p95 и RPS, одно найденное и исправленное узкое место (модуль 6)
7. **ИИ-функция:** одна функция на LLM с таймаутами, лимитами, оценкой стоимости и набором для eval (модуль 7)
8. **Контейнеры:** всё поднимается через `docker compose up` (модуль 8); манифесты k8s по желанию (модуль 9)
9. **Безопасность:** модель угроз, пройденный чек-лист OWASP, сканирование зависимостей и образов в CI (модуль 10)
10. **Инфраструктура:** свой домен, HTTPS, деплой из CI, бэкапы, мониторинг доступности (модуль 11)
11. **Запуск:** базовое SEO, аналитика с целями, запуск минимум в одном канале, данные за неделю (модуль 12)

## Проект
«Slot» из курса или собственная идея сопоставимого размера, согласованная с преподавателем.

## Защита (10 минут)
- Живое демо на продакшен-адресе
- Диаграмма архитектуры и три самых важных ADR
- Что ломалось во время курса и как вы это чинили
- Результаты запуска: посетители, конверсии, что бы вы изменили
- «Что изменится при ×10 пользователей?»

## Результат
Репозиторий + живой адрес + диаграмма архитектуры + ADR + отчёт о запуске.
