# Модуль 5 — Базы данных: модель, транзакции, масштаб

## Цели обучения
- Моделировать данные так, чтобы бизнес-правила соблюдала сама база данных
- Понимать транзакции и уровни изоляции и предотвращать гонки вроде двойной записи
- Менять схему работающей БД без простоя
- Выбирать подходящее хранилище для каждого вида данных и знать порядок масштабирования

## План лекции
1. Почему БД — сердце приложения: данные живут дольше кода; ошибки в данных — самые дорогие
2. Моделирование данных: сущности и связи, ключи, нормализация и когда денормализовать
3. Ограничения как бизнес-правила: `NOT NULL`, `CHECK`, `UNIQUE`, внешние ключи, частичные уникальные индексы, `EXCLUDE` для пересекающихся интервалов времени
4. Транзакции и ACID
5. Гонки: «проверил, потом вставил», потерянные обновления; решения — ограничения, условный `UPDATE`, `SELECT … FOR UPDATE`
6. Уровни изоляции в PostgreSQL: Read Committed, Repeatable Read, Serializable; аномалии и повторы
7. Индексы подробно: B-tree и порядок колонок, частичные, покрывающие, GIN/GiST; цена индексов при записи
8. Миграции без простоя: expand → migrate → contract; опасные операции и `CREATE INDEX CONCURRENTLY`
9. JSONB: когда полуструктурированные данные в PostgreSQL — нормально
10. Выбор хранилища: PostgreSQL по умолчанию; Redis, MongoDB, ClickHouse, поисковые движки, объектное хранилище, векторный поиск
11. OLTP vs OLAP: не гоняйте аналитику по продакшен-БД
12. Порядок масштабирования: запросы и индексы → вертикально → пул соединений → реплики (и задержка репликации) → кэш → партиционирование → шардирование
13. Бэкапы и восстановление на момент времени (WAL)
14. БД и ИИ-агенты: роли только на чтение, миграции через ревью, никогда — запись в продакшен

## Лабораторная работа
Пересоберите схему «Slot» с ограничениями, при которых двойная запись невозможна (частичный уникальный индекс, `EXCLUDE` для пересекающихся слотов). Напишите тест, который отправляет 50 одновременных записей на один слот и доказывает, что проходит ровно одна. Проведите одну миграцию без простоя (expand → migrate → contract) во время нагрузочного теста.
- **С агентом:** попросите агента предложить схему по ER-диаграмме из Модуля 1 и написать тест на конкурентность; каждое предложенное ограничение проверьте, попытавшись его нарушить.

## Результат
Миграции, зелёный тест на конкурентность, лог миграции без простоя с нулём упавших запросов и ADR о выборе хранилищ.
