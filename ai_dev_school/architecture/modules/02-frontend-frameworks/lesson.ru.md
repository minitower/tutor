# Модуль 2 — Фронтенд-фреймворки: как выбирать

## Цели обучения
- Понимать, как устроен современный фронтенд изнутри
- Знать основные фреймворки и мета-фреймворки и в чём сильна каждая из них
- Выбирать фреймворк под задачу на основе аргументов, а не хайпа

## План лекции
1. От jQuery к компонентам: DOM, компоненты, props, состояние
2. Модели реактивности: виртуальный DOM (React), прокси/сигналы (Vue, Solid, сигналы в Angular), компилятор (Svelte)
3. Стратегии рендеринга: SPA, SSR, SSG, ISR, islands, гидратация, React Server Components; что каждая значит для SEO и скорости
4. UI-библиотеки: React, Vue, Angular, Svelte, Solid; экосистема, порог входа, рынок труда
5. Мета-фреймворки: Next.js, Nuxt, SvelteKit, Astro, React Router (бывший Remix); роутинг, загрузка данных, серверный код
6. Инструменты: Node.js, npm/pnpm, Vite, TypeScript, линтеры
7. Стилизация: CSS-модули, Tailwind, библиотеки компонентов (shadcn/ui, MUI, Vuetify)
8. За пределами браузера: React Native, Flutter, Tauri/Electron, PWA
9. Матрица выбора: нужен ли SEO, интерактивность, навыки команды, экосистема, найм, хостинг
   - Контентный сайт / блог / лендинг → Astro или SSG
   - SEO и приложение в одном → Next.js / Nuxt
   - Внутренняя админка / дашборд → SPA (React или Vue + Vite)
   - Большая корпоративная команда → Angular
10. Производительность фронтенда: размер бандла, Core Web Vitals, Lighthouse

## Лабораторная работа
Сделайте публичную страницу «Slot» (SSR/SSG, нужен SEO) и админ-панель (SPA) на mock API. Прогоните Lighthouse по обеим.
- **С агентом:** дайте агенту user stories из модуля 1 и дизайн-токены; попросите собрать экраны админки; проверьте результат по критериям приёмки.

## Результат
Два фронтенда + отчёты Lighthouse + одностраничный ADR «почему этот фреймворк».
