## Проблема: синхронизировать данные и экран

```js
// jQuery-стиль: каждое изменение данных — ручная правка DOM
slots = slots.filter(s => s.id !== bookedId);
$('#slot-' + bookedId).remove();
$('#free-count').text(slots.length);
if (slots.length === 0) $('#empty').show();
// забыли одну строку — экран врёт
```

Фреймворк решает это так: **вы описываете, как экран зависит от данных, а он сам обновляет DOM**.

## Компоненты, props, состояние

```jsx
function SlotList({ slots, onBook }) {          // props — вход
  const [selected, setSelected] = useState(null); // состояние
  if (slots.length === 0) return <p>Свободных слотов нет</p>;
  return (
    <ul>
      {slots.map(s => (
        <SlotItem key={s.id} slot={s}
          active={s.id === selected}
          onClick={() => setSelected(s.id)} />
      ))}
    </ul>
  );
}
```

UI = функция(состояние). Компонент — переиспользуемый кусок интерфейса.

<!-- Slide 6 -->
## Модели реактивности

| Модель | Как узнаёт об изменениях | Кто использует |
|---|---|---|
| **Virtual DOM** | Перерисовывает дерево в памяти и сравнивает (diff) | React |
| **Прокси / сигналы** | Отслеживает, кто читал значение, обновляет только их | Vue, Solid, Angular (signals), Preact signals |
| **Компилятор** | Ещё на сборке превращает компонент в точечные обновления DOM | Svelte |

Для пользователя разница обычно невидима; для размера бандла и скорости на слабых телефонах — заметна.

<!-- Slide 7 -->
## Стратегии рендеринга

| Стратегия | Где строится HTML | Когда |
|---|---|---|
| **SPA** | В браузере, после загрузки JS | Админки, дашборды, всё за логином |
| **SSR** | На сервере, на каждый запрос | Страницы с SEO и свежими данными |
| **SSG** | На сборке, один раз | Лендинги, блоги, документация |
| **ISR** | На сборке + пересборка по таймеру | Каталоги, которые меняются редко |
| **Islands** | Статичный HTML + интерактивные «острова» | Контентные сайты с немного интерактива |

---

<!-- Slide 8 -->
## SPA vs SSR: что видит поисковик

**SPA:** сервер отдаёт пустую страницу и большой JS

```html
<body><div id="root"></div><script src="app.js"></script></body>
```

**SSR / SSG:** сервер отдаёт готовый HTML, JS «оживляет» его (**гидратация**)

```html
<body><h1>Барбершоп «Борода»</h1><ul><li>Пт 15:00 — свободно</li>...</ul></body>
```

Поисковики умеют исполнять JS, но медленнее и не всегда. Для публичных страниц — SSR/SSG.

## React Server Components

- Часть компонентов выполняется **только на сервере**: ходят в БД, не попадают в бандл
- Клиентские компоненты (`"use client"`) — только там, где нужна интерактивность
- Меньше JS в браузере, данные без отдельного API-слоя
- Цена: сложнее ментальная модель, нужен мета-фреймворк (Next.js)

<!-- Slide 10 -->
## UI-библиотеки

| | Сильные стороны | Слабые стороны |
|---|---|---|
| **React** | Крупнейшая экосистема и рынок труда | Много решений «выбери сам» |
| **Vue** | Мягкий порог входа, всё из коробки | Меньше вакансий за рубежом |
| **Angular** | Полный фреймворк, строгая структура, TypeScript | Тяжёлый, крутая кривая обучения |
| **Svelte** | Минимум кода и JS, компилятор | Меньше экосистема |
| **Solid** | Сигналы, очень быстрый | Маленькое сообщество |

<!-- Slide 11 -->
## Мета-фреймворки

UI-библиотека рисует компоненты. **Мета-фреймворк** добавляет: роутинг, загрузку данных, SSR/SSG, серверный код, сборку.

| Библиотека | Мета-фреймворк |
|---|---|
| React | **Next.js**, React Router (бывший Remix) |
| Vue | **Nuxt** |
| Svelte | **SvelteKit** |
| Любая | **Astro** — контент + острова из любых компонентов |

---

## Инструменты

- **Node.js** — запускает инструменты сборки и серверный код
- **npm / pnpm** — пакеты; `package.json` + lock-файл
- **Vite** — дев-сервер с мгновенной перезагрузкой и сборка для продакшена
- **TypeScript** — типы ловят ошибки до запуска; для агентов тоже подсказка
- **ESLint, Prettier** — единый стиль

```bash
npm create vite@latest slot-admin -- --template react-ts
```

## Стилизация

| Подход | Как | Когда |
|---|---|---|
| CSS-модули | Обычный CSS, имена классов изолированы | Просто и надёжно |
| **Tailwind** | Утилитарные классы прямо в разметке | Быстро, однородно; популярно у агентов |
| Библиотеки компонентов | shadcn/ui, MUI, Vuetify, Ant Design | Админки: таблицы, формы, модалки готовы |

Для агентов важно одно: **единые токены дизайна** (цвета, отступы), иначе каждый экран будет в своём стиле.

## За пределами браузера

| Задача | Варианты |
|---|---|
| Мобильное приложение | React Native, Flutter, нативные Swift/Kotlin |

<!-- Slide 15 -->
## Матрица выбора

| Задача | Рекомендация |
|---|---|
| Контентный сайт, блог, лендинг | **Astro** или SSG |
| SEO + приложение в одном | **Next.js** / **Nuxt** |
| Внутренняя админка, дашборд | **SPA**: React или Vue + Vite |
| Большая корпоративная команда | **Angular** |
| Максимально лёгкий интерактив | **Svelte / SvelteKit** |

Плюс: что знает команда, какой хостинг, кого можно нанять.

<!-- Slide 16 -->
## Вопросы перед выбором

1. Нужен ли **SEO**? → SSR/SSG
2. Сколько **интерактива**? → от островов до SPA
3. Что **уже знает команда**?
4. Есть ли **готовые компоненты** под задачу?
5. Где будет **хостинг**? (Vercel и Next.js, статика на CDN)
6. Кого вы сможете **нанять** через год?

Фиксируем ответ в ADR.

## Производительность фронтенда

- **Core Web Vitals:** LCP (загрузка главного), INP (отклик на действие), CLS (прыжки вёрстки)
- Главный враг — **размер JS**: каждый килобайт надо скачать, разобрать и выполнить
- Приёмы: разбиение кода, ленивая загрузка, оптимизация картинок, меньше зависимостей
- **Lighthouse** в DevTools — бесплатный аудит за минуту

## «Slot»: две разные задачи — два подхода

| | Публичная страница | Админка |
|---|---|---|
| Кто смотрит | Клиенты и поисковики | Только мастер |
| SEO | Критично | Не нужно |
| Интерактив | Немного: выбрать слот | Много: календарь, таблицы |
| Подход | SSR/SSG (Next.js или Astro) | SPA (React + Vite) |

Один продукт — не обязательно один фреймворк.
