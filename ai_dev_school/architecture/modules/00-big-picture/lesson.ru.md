# Модуль 0 — Общая картина: как устроено современное приложение

## Цели обучения
- Объяснить, что такое фронтенд, бэкенд и инфраструктура и как они общаются между собой
- Объяснить, почему в каждом слое используются именно эти языки
- Проследить путь одного запроса от браузера до базы данных и обратно

## План лекции
1. Модель клиент–сервер: кто спрашивает, кто отвечает, где живут данные
2. Жизнь запроса: URL → DNS → TCP/TLS → CDN → балансировщик / reverse proxy → API → БД → ответ → отрисовка
3. Протоколы и форматы: методы и коды HTTP, REST, JSON, WebSocket, gRPC, GraphQL (обзор)
4. Фронтенд: браузер исполняет только HTML/CSS/JS (+ WebAssembly); почему TypeScript компилируется в JS; мобильные и десктопные клиенты
5. Бэкенд: на сервере может работать любой язык; что определяет выбор (экосистема, скорость, команда, рынок найма)
6. Инфраструктура: серверы, сети, базы данных, очереди, CDN; языки конфигурации и IaC (YAML, HCL, Bash)
7. Архитектурные стили: монолит, модульный монолит, микросервисы, serverless; почему большинству проектов стоит начинать с монолита
8. Где здесь ИИ: LLM API как ещё одна зависимость бэкенда; агенты как новый тип клиента

## Лабораторная работа
Откройте DevTools на реальном сайте (маркетплейс или новостной сайт). Проследите одну загрузку страницы: время DNS, HTML-документ, статика, API-запросы, тайминги. Нарисуйте архитектуру, которую можно восстановить снаружи.
- **С агентом:** дайте агенту трассу (HAR-файл) и попросите объяснить каждый запрос; проверьте, где он ошибся.

## Результат
Размеченная трасса запросов + первая блок-схема «Slot» (клиент, API, БД, уведомления).
